## Findings fixed

1. **Contradictory eligibility bodies could be accepted.** The original permissive
   parsers ignored error/status fields alongside affirmative eligibility and ignored
   decision fields alongside a pending response. Eight regression cases now return
   `unknown`. Sample recognisers live in the web schema directory. They are conservative
   body recognisers, not a complete provider schema or verified HTTP response contract.
2. **Formatting large amounts could lose a kobo.** `fromMinor(9007199254740991)`
   previously returned an imprecise JavaScript number. It now returns the exact decimal
   string `90071992547409.91` using integer arithmetic. There are no production callers
   to migrate. Callers must preserve this string contract when displaying/sending money.

## Smallest useful provider question list

for one authoritative integration pack answering these five groups:

1. **Access:** exact API base per environment, secure test credentials, test identities,
   OTPs and outcome fixtures, rate limits, and token expiry/rotation behavior.
2. **Customer journey:** new/existing customer field and status contracts, KYC sequencing,
   hosted/headless capabilities, bank-statement responsibility, and authoritative offer
   terms/schedule plus acceptance requirements. Statements remain undocumented; do not
   assume they are unnecessary or that Baci must collect them.
3. **Money and fulfilment:** currency/amount units, principal versus equity, tenure,
   approval/activation meaning, dispatch authorization, settlement and refund rules.
4. **Recovery and events:** webhook payloads/authentication, event identifiers/retries,
   authoritative status lookup, and per-mutation idempotency/response-loss recovery.
5. **Account mapping:** partner versus merchant provisioning, merchant references and
   payout beneficiary binding, territorial eligibility and privacy/retention duties.
