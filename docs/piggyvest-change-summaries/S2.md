# S2: master kill switch for new-money paths

## What changes
One environment setting, the master kill switch, now stops every way new money can enter the PiggyVest wallet. This includes the three webhook intake points that queue provider deposits, signed card events and paid interest. It also covers the existing per-feature gates. The read-only wallet view keeps working while the switch is on.

## Why
During an incident the owner needs one switch that stops new deposits at once. The first version missed the intake gates, so a deposit could still be queued while the switch was on. It also left customers unable to see their balance.

## What could go wrong and how it is prevented
- A module reads its own enable flag and skips the switch. A sweep test now fails if any non-test file outside the shared switch file reads an enable flag directly.
- Money already accepted by the provider could be stranded. The workers and drain readers never consult the switch, so accepted deposits still settle. Tests check both the intake refusal and the worker still loading.
- Customers could be locked out. The wallet view falls back to the read-only reader under the switch, and wallet setup recovery, which can promote a wallet, is skipped.
- Cancel to main and reconcile are untouched and stay available.
- A typo in the switch value fails closed, since only unset or exactly false means off.

## How it is tested
New tests cover each intake gate with the switch on and off, the worker and drain readers under the switch, the wallet view under the switch, and the sweep for direct flag reads.

## How it stays switched off
No new setting is turned on by this change. Every feature flag keeps its current default, so nothing new is active in production. The switch only ever restricts.
