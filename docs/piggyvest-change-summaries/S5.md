# Ask for the PIN before money moves into a savings goal

## What changes

Moving money from the wallet into a savings goal now needs a PIN check.
The customer enters their transaction PIN, the server checks it and hands
back a short-lived proof, and the funding step spends that proof in the
same database step that sets the money aside. The proof is for one goal,
one transfer and one amount. A new route performs the PIN check.

Proof types for cancelling and completing a goal are added too, with a
database helper that checks the goal belongs to the customer. Those flows are
not connected yet.

The database login that runs savings transfers can no longer call the old
funding step directly.

The database decides whether a proof is needed. A merchant with PIN checking
off keeps funding goals with no proof, exactly as before, so the phone app
keeps working for them. A merchant with PIN checking on needs a proof, and
the app only gets a refusal asking for the PIN once such a merchant exists.

## Why

A stolen session should not be enough to move money into a goal.

## What could go wrong and how it is prevented

- A transfer set aside without a proof: the proof is spent in the same
  step, and a refused proof undoes the transfer completely.
- A proof reused, or used for another amount or goal: each proof is single
  use and tied to the exact goal, transfer and amount.
- An old proof used late: proofs last two minutes, and the clock is read
  after the proof is locked.
- Retrying a transfer already set aside: no second proof needed.

## How it is tested

Database tests check refusal when the proof is missing, unknown, expired,
or for another amount, purpose, goal or transfer, or when the merchant is
switched off. Nothing is set aside and the proof stays unspent. They also
check that the exact proof reserves the transfer, that a replay needs no
proof, that a merchant with PIN checking off funds without one, and that cancel and complete proofs are spent only for the
customer's own goal. Unit tests cover the route, the request rules and the
proof binding.

## How it stays switched off

PIN checking is off for every merchant and the PIN secret is not set, so
funding behaves as it does today. Nothing is enabled in production by this
change. Turning PIN checking on for a merchant must wait for the phone PIN
screen.
