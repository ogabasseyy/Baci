# Ogabassey gift-card pilot

The browser preview and the supervised worker are separate. The worker requires a durable, already-paid gift-card order ID. The live confirmation form is available only to the signed-in pilot customer when explicitly enabled. It performs a fresh supplier and Juicyway price check again before debiting. All quote refreshes reuse the configured pilot order ID, so they cannot initiate a second debit or supplier order.

Before a live pilot, deploy and verify the wallet authorization and order creation path, the worker migrations, and the callback endpoint. Give a dedicated `LOGIN NOINHERIT` identity membership in `gift_card_petrock_worker` with `SET` allowed and no direct access to order tables. Use a direct PostgreSQL connection for the worker. It selects the worker role at connection startup. Verify `current_user` is the worker role and `session_user` is the dedicated login before enabling the pilot. Use the repository's managed secret store for `GIFT_CARD_WORKER_DATABASE_URL`, `PETROCK_API_BASE_URL`, `PETROCK_API_TOKEN`, and `GIFT_CARD_EVIDENCE_KEY_HEX` (32 random bytes, hex). Configure the feedback URL for the deployed gift-card callback using its independent `GIFT_CARD_PETROCK_CALLBACK_TOKEN`. The worker and checkout share the same fixed product, supplier cost, and approved charge for this one pilot. The database allowlist must match them. Verify this invariant when reviewing changes to the pilot.

Keep the pilot disabled until the worker and callback are verified. Provision the quote HMAC as `GIFT_CARD_WALLET_QUOTE_HMAC` for the web server and as `gift_card_wallet_quote_hmac` in database Vault, with identical values. Configure `GIFT_CARD_PILOT_USER_ID` and a unique `GIFT_CARD_PILOT_ORDER_ID`. Store the same order UUID in Vault under `gift_card_petrock_pilot_order_id` before enabling the pilot. The worker RPCs refuse other orders and refuse access when the Vault entry is missing or ambiguous. When the reviewed path is deployed, set `OGABASSEY_GIFT_CARD_PILOT=true` for this pilot only. Reconfirm the exact Juicyway total, wallet availability, and Petrock cost before the customer signs in and confirms the wallet charge. Stop if the fresh total differs from the approved ₦16,735.73 and obtain a new approval before changing the pilot amount. A catalog selection from storefront search waits for Get current price. Public previews can remain cached for up to 60 seconds after rate-key rotation. Wallet confirmation always gets a fresh rate. Record the paid order UUID and wallet ledger reference. Have the worker ready before the customer confirms and submit immediately in the same supervised session. The worker rechecks the USD offer and available supplier balance before claiming the order. This leaves the order unclaimed if the supplier check fails. The already-debited NGN amount is fixed by the fresh confirmation quote. Later exchange-rate movement does not change that debit. Run the worker once for that order:

```sh
pnpm --filter @baci/web process:gift-card-petrock-order submit <paid-order-uuid>
pnpm --filter @baci/web process:gift-card-petrock-order poll <paid-order-uuid>
```

The worker durably claims the order before placing it with Petrock. If it stops in `submitting` or `submission_unknown`, reconcile with Petrock by the paid order UUID as the supplier reference. Do not run another placement or refund until supplier acceptance or non-placement is confirmed. Polling reads Petrock once the provider order ID is recorded. A matching terminal rejection atomically refunds the wallet once. A matching success records fulfillment. Unknown, missing or mismatched evidence does not trigger a refund. The callback returns 204 for a valid token and discards the body without recording fulfillment. The response does not request a retry. The operator runs the worker poll command against the existing order until it captures a terminal response from Petrock’s authenticated order API; do not treat callback delivery as fulfillment. If polling reports a missing or mismatched reference, reconcile the existing order with Petrock before accepting the result. Do not submit again.

The terminal audit prints the order reference, normalized supplier state, and `[redacted]` in place of the replay. The replay itself is encrypted with an order-bound AES-GCM key for restricted inspection. The voucher format and customer delivery still need a sanitized completed response. Never copy the raw replay or voucher into PRs, logs, or shared fixtures.

Petrock accepts the callback URL in its order fields. Its path token only routes to the discard-only handler and cannot read or change an order. The URL may appear in provider and ingress access logs, so use a dedicated random token, restrict access to those logs, and rotate the token after the pilot or if the URL is exposed. Keep this token separate from database, wallet-signing, and Petrock API credentials. Use independently authenticated callbacks before accepting any fulfillment data.

If the supplier price check fails before the claim, the order remains paid and unattempted. A database owner can call `private.refund_unplaced_gift_card_pilot_order(order_id)` to cancel and credit it once. For an order in `submission_unknown`, get written confirmation from Petrock that no order was accepted for the customer's order UUID. With the worker stopped, a database owner can call the same function with the order ID and the Petrock support receipt ID as the second argument. Use the receipt ID only. Do not put voucher codes or customer data in it. A timeout alone cannot authorize a refund. If the worker stopped in `submitting`, confirm it is no longer active, obtain Petrock's verdict, and use the existing submission RPC to record the verified supplier ID or transition to `submission_unknown` after confirmed non-placement. The refund RPC is unavailable to app callers and the worker login.

The authenticated Petrock reseller catalog returned HTTP 200 for `GET /api/reseller/v1/products?product_id=2844` on 2026-11-21. The product was PlayStation Gift Card [PSN] USA $10 in USD and its field list contained only `{"name":"Quantity","type":"quantity","required":true}`. The wire test for product 2844 asserts `Quantity: 1` plus the standard `reference_id` and `feedback_url` fields. No customer email or PSN identifier was advertised. This was a read-only catalog check. Do not treat it as a completed order or fulfillment receipt.
