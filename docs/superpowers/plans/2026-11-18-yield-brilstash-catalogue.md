# Yield / BrilStash Catalogue Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task after review. Steps use checkbox syntax for tracking.

**Goal:** Supply a reviewed Ogabassey sellable catalogue to BrilStash through its nightly paginated pull contract.

**Architecture:** A web-specific adapter builds validated immutable generations from tenant-scoped public-safe catalogue facts and a durable listing identity map. The dedicated partner route serves array pages from one generation, without request-time full-catalogue builds. Existing Google/Facebook feeds retain their behavior.

**Tech Stack:** Repository TypeScript, Next.js route handlers, Zod, Supabase/PostgreSQL under RLS, Vitest, pnpm/Turborepo and Biome; verify installed versions before implementation.

**Spec:** [Catalogue pilot, contract, reuse assessment and acceptance cases](../../partners/brilstash/2026-11-18-catalogue-pilot.md).

## Global constraints

- Planning and synthetic local sample preparation are authorized now. Live publication and partner communications remain pending review. The pilot requires a fresh BrilStash installation in each environment, with imports disabled through Baci activation and feed verification.
- `GET /partners/yield/brilpay/products`; JSON array; 1–10 HTTPS images; 10-second budget per page; nightly 23:59 Africa/Lagos pull.
- Preserve stable offer identity, exact conditions, NGN prices and true zero stock. Do not infer supported order, quote or fulfilment APIs from CrossRem.
- No service-role/admin clients for user-facing operations, protected-file/env edits without explicit authorization, old migration edits, production data changes or deployment in this task.
- Preserve unrelated dirty work. Stage only task files. New PRs are drafts; run required CodeRabbit review before committing/shipping runtime code.

## Review focus

- A zero authoritative quantity with positive legacy stock must never revive availability (Task 1).
- New/used storage variants must select their own PDP, image, price and stock without a parent duplicate (Task 1).
- Missing facts on an already published listing must not cause accidental channel deletion (Task 2).
- A pull spanning source changes or generation promotion must not mix generations (Tasks 2–3).
- A failed middle page must preserve the partner's prior complete import (Task 4, requires partner evidence).
- The exact feed path must reach the handler and preserve authorization on the agreed hostname (Tasks 0 and 3).
- An otherwise valid unapproved listing must be excluded. A revoked generation must stay unavailable through retries and concurrent builds (Task 2).
- Filtered pulls must leave out-of-scope partner listings active (Task 4, requires partner evidence).

## File structure and interfaces

All following files are proposed; no runtime implementation is included in this planning task.

| File | Responsibility |
| --- | --- |
| `apps/web/src/schemas/brilstash-feed.ts` | Product/query schemas and inferred types |
| `apps/web/src/lib/brilstash/build-catalogue.ts` | Pure sellable-row expansion, descriptions, prices, quantities, images and URLs |
| `apps/web/src/lib/brilstash/load-catalogue.ts` | Explicit, bounded, merchant-scoped source acquisition |
| `apps/web/src/lib/brilstash/catalogue-snapshot.ts` | Immutable generation construction, validation and atomic promotion |
| `apps/web/src/scripts/build-brilstash-catalogue.ts` | One-shot staging command for the authorized scheduler |
| `apps/web/src/scripts/manage-brilstash-catalogue.ts` | Authenticated operator preview, approvals, drain, promotion, release tracking, suspension and resumption |
| `apps/web/src/lib/brilstash/partner-access.ts` | Bearer parsing and invocation of the restricted page-read RPC |
| `apps/web/src/app/partners/yield/brilpay/products/route.ts` | Partner path, array pagination, safe errors and totals |
| `supabase/migrations/<actual-UTC-timestamp>_brilstash_catalogue.sql` | Permanent partner installation bindings, approvals, listing identities, categories, versioned listing facts, immutable generations, released attempt records, revocation and database access |

Colocate each file's tests as `*.test.ts`. Choose the migration timestamp at implementation time. Do not create a proxy rewrite for this path; inspect current routing/host middleware read-only and seek specific authorization if it requires a protected-file change.

Domain interfaces: `SellableSource` is a discriminated union of public product/variant/offer facts with merchant ID, source ID, exact condition, selected attributes, authoritative stock provenance, NGN price, verified images, canonical URL and reviewed box/warranty facts. `BrilStashProduct` is inferred from the product schema, matching the spec. `ListingIdentityMap` maps merchant/installation/source references to immutable external IDs. `CatalogueBuildResult = { products: BrilStashProduct[]; rejected: { sourceRef: string; code: string }[] }`. `CatalogueSnapshot = { generationId: string; merchantId: string; installationId: string; generatedAt: string; mappingVersion: string; factsRevisionsByExternalId: Record<string, string>; products: BrilStashProduct[] }`. These internal metadata fields never wrap the response array.

### Task 2: Acquire and persist complete tenant-scoped generations

**Files:** Create `load-catalogue.ts`, `catalogue-snapshot.ts`, the builder and operator scripts, the migration and colocated tests. Reuse existing source acquisition only where its cap, consistency and stock provenance are made explicit.

**Interfaces:** `loadBrilStashSources(installationId: string): Promise<{ sources: SellableSource[]; catalogueRevision: number; expectedActiveGenerationId: string | null; sourceReadAt: string }>` reads one consistent source snapshot. `stageBrilStashSnapshot(installationId: string): Promise<{ candidateId: string }>` runs as the builder and never changes serving. In drain mode the operator calls `closeBrilStashAdmission(installationId, candidateId, windowDateLagos)` to receive a closure revision and `recordBrilStashDrainEvidence(installationId, closureRevision, evidence)` to record disposition. `promoteBrilStashSnapshot(installationId, candidateId, windowDateLagos, expectedClosureRevision?)` is a separate operation. Require closure evidence and operator authority in drain mode. Permit a scoped promotion entitlement for the confirmed sequence mode only after its checks pass. `approveBrilStashCandidate(installationId, candidateId, expectedPayloadDigest)` is operator-only and records approval of the exact immutable staged payload displayed by the CLI. `activateFirstBrilStashSnapshot(installationId, candidateId, windowDateLagos, partnerHistoryEvidenceId, candidateApprovalId)` is operator-only and checks the approval against the candidate ID, binding, catalogue revision and digest in the activation transaction. Under the installation lock require a staged valid initial candidate, no active pointer, no prior activation marker, and single-use approved evidence for that exact fresh partner installation of no prior imported or staged catalogue, no pending jobs and disabled scheduled and manual imports. Persist an activation marker referencing the approved candidate and digest, and consume the fresh partner evidence in the activation transaction. Provision the partner binding separately under merchant operator authorization. Use an unconditional database unique constraint on the canonical partner installation identity in each environment and allow only one binding per Baci installation. Enforce merchant consistency and reject reassignment or deletion, including ordinary cleanup cascades. Include partner account ID only if BrilStash scopes installation identifiers to accounts. Before a held release, `recordBrilStashReleaseRequest(installationId, verifiedAttempt)` creates the durable operator-owned record. `recordBrilStashAttemptDisposition(installationId, releaseId, partnerEvidence)` records exact-attempt partner readback. Terminal dispositions are complete application, confirmed cancellation or discard without application, or verified partial-application reconciliation. An unreconciled partial application remains open. A lost active pointer after first activation goes to recovery. Aborting a drain invalidates its evidence, and urgent suspension has its own operator-only resume path. `read_brilstash_page(bearer, page, limit, min_price, generation_token)` resolves the installation internally and returns the page and totals. Include the wire token only if confirmed by the partner. Durable identity allocation and mapping remain internal to snapshot construction.
