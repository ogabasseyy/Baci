### Finance evidence import

- Finance supplies a reconciled till closeout or settled POS evidence export. Its controlled exporter signs the exact UTF-8 JSON bytes with Ed25519. Each batch carries version `1`, `sourceId`, `merchantId`, `targetOrigin`, `issuedAt` and up to 50 `receipts`. Each receipt has `orderId`, `method`, `status`, `amountMinor`, `receiptReference`, `reconciliationReference` and `occurredAt`. The cash status is `reconciled_cash` and the POS status is `settled_pos`. References identify the stable receipt or acquirer result and its independent reconciliation record.
- The importer trust registry contains each source's `id`, `merchantId`, `methods`, `targetOrigin` and Ed25519 `publicKeyPem`. Provision the service credential as `BACI_TENDER_IMPORT_SERVICE_KEY` and the explicit target URL as `BACI_TENDER_IMPORT_URL` in the importer environment.

```sh
pnpm --filter @baci/web exec tsx tools/paid-order-amendment-evidence/cli.ts <manifest.json> <signature.b64> <trust-registry.json>
```

- Keep the source's signing key in the Finance exporter and the service credential in the importer. The signature covers the destination, merchant, verification verdict and all receipt fields. Baci checks each order against the signed merchant inside the atomic registration transaction. An invalid entry rolls back the batch. The exact replay returns the same evidence IDs. The order's existing confirmation command applies an evidence entry once.
- The latest full chronological migration replay converged on Supabase PostgreSQL 17.6. All six requested SQL checks passed, including the importer, verified tender settlement, prior funding, Paystack settlement, pause and function exposure.

## Pause procedure and rollback

1. Set the selected merchant's admission flag `enabled=false` and advance the configuration version through the platform operator boundary. Leave the record, the verified integration and the workers needed by admitted obligations in place. Leave `automated_paystack_refunds` enabled when the intent is to stop only new changes.
2. For a provider incident, set `automated_paystack_refunds=false` to prevent new database dispatch authorizations. An already-authorized worker may still send its Paystack request. Treat those attempts as in flight and continue reference lookups, capture-history reviews, webhook verification and merchant adjustments. Retain the worker credentials and global reconciliation worker while obligations are unresolved. Inventory the open amendments, payment claims, refund attempts, queued notifications and unresolved bank entries.
3. With a configuration row present, even disabled, the ordinary checkout admission RPC keeps its instrument fence. The disposable test proved that the supported Paystack card claim with tracking proof works while paused and that the DVA claim is rejected. Qualify the intended merchant's ordinary checkout channels before adding the configuration row. Leave the row absent for merchants outside the pilot. The `integration_wallet_checkout` opt-in defaults to false and is independent of `enabled`. Keep it off in production until wallet collection is approved. Existing checkout claims keep the collection route they were initialized with.
4. Use pause and a forward fix. No older compatible application revision has been qualified for rollback after amendments exist. Preserve the guards, settlement and cancellation workers, versioned document readers and audit records through any fix.
5. Use **Recheck refund history** on an unsent attempt in review. The worker rechecks the original capture with the admitted Paystack integration and records clearance only when the observed competing refund IDs are verified as failed, current provider history has no other competing refund, and the local ledger is clear. The next worker pass checks provider history and authorization again before dispatch. Send a processed, still-active, missing or unidentified competing refund to Finance for ownership and coverage reconciliation. Do not send a replacement refund or lift the hold while that evidence is unresolved.
