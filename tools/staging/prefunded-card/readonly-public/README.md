# Read-only first-card public restoration

This owner procedure restores authenticated capability reads, not card funding.
Mutation permission defaults off in the compiled launcher and HTTP/runtime
boundaries. The pinned Docker image must not inherit a mutation flag. Owned
goal reads return `enabled=false`, `maximumAmountKobo=0`; valid POST and PATCH
return 503 before payment composition. Saved cards and financial workers stay
off. The fixed stop deadline is 6 October 2026, 15:59:10 UTC.

The predecessor is the installed retirement archive/manifest, not the original
Docker label. Pins are intentionally different. The receipt, every artifact
file, configuration, effective units and full protected database snapshot are
checked. Only the three checkout expiry fields and two unit deadline fields
change. No database mutation, role renewal or payment starts here.

Candidates are private and the old tree is retained by rename-aside. Rollback
attempts every recovery step independently, removes only the verified owned
candidate container, retains failed artifacts, restores all original units and
recreates the predecessor stopped. Secondary recovery errors are recorded.

`owner.py <sealed-root-bundle> --check` runs the protected read-only preflight.
Without `--check`, it installs only this fixed read-only release. Do not use it
as a generic updater: paths, source closure, predecessor and candidate pins are
deliberately specific. The human-approved root console invocation seals all
helper bytes before execution; no owner command is delegated back to the user.

`verify-denials.py` authenticates the existing synthetic customer privately.
It requires the disabled capability before attempting either denial probe,
never follows redirects, bounds response sizes and does not print credentials.
Independently check the protected database state afterward.
